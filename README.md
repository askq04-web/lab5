# Лабораторная 5

Продолжение лабораторной 4. Java 21, Maven, PostgreSQL.

Если база из четвёртой работы уже есть, выполните под postgres только `db/5_sessions.sql` в базе `lab_samples`. Для новой базы выполните скрипты `1_create_db.sql` — `5_sessions.sql` по порядку. Указания по подключению есть в начале скриптов.

Скопируйте `.env.example` в `.env`, укажите подключение к БД и свой `JWT_SECRET` длиной не менее 32 байт. Срок access по умолчанию — 900 секунд, refresh — 604800 секунд. Они меняются через `JWT_ACCESS_SECONDS` и `JWT_REFRESH_SECONDS`.

Запуск: `mvn spring-boot:run` или класс `Lab4Application` в IntelliJ IDEA. Рабочая папка запуска — корень проекта `lab5`.

Запросы находятся в `requests.http`. Первые пять шагов выполняйте по порядку. После входа, обновления и повторного использования старого refresh смотрите таблицу через `db/check_sessions.sql`. Начинать удобнее с пустой таблицы сессий. Тестовые учётные записи: `ivanov / Customer1`, `laborant / Laborant1`, `admin / Admin1234`.

Вход и регистрация возвращают access и refresh. Access передаётся в `Authorization: Bearer ...`, refresh — в JSON. CSRF-токен больше не нужен: приложение не использует cookie для аутентификации и не создаёт HTTP-сессии.

Каждая пара хранится отдельной строкой. При обновлении старая строка блокируется до конца транзакции и получает USED, новая — ACTIVE. Повтор старого refresh меняет USED на REVOKED. Сервис завершает транзакцию, затем контроллер возвращает 401. Поэтому отзыв сохраняется. Ошибка записи новой пары откатывает транзакцию целиком. При регистрации в ту же транзакцию входит создание пользователя.

Проверка: `mvn test`. Тесты используют отдельную БД H2 и проверяют HTTP-коды, типы и claims JWT, смену статусов, блокировку пользователя, откат при ошибке записи и два одновременных обновления.
